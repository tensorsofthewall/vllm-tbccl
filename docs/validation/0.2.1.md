# vllm-tbccl 0.2.1 validation (draft)

```{warning}
**This is not a certification.** vllm-tbccl 0.2.1 is a patch release of 0.2.0 that adds the benchmark provider. The runtime evidence of the previous release stands because no runtime code changed; this page records what is specific to 0.2.1. The release has not been published yet, so the release-artifact checks below are listed as not done.
```

## What changed

The benchmark provider (`benchmarks/provider`, provider protocol 1) and its documentation. The platform plugin, the pipeline communication, vLLM 0.31.0, the vllm-metal fork pin, PyTorch 2.13.x, TBCCL C ABI 1 and wire protocol 4 are unchanged. The provider also accepts the macOS vLLM wheel version `0.31.0+cpu` (it ignores the local version label).

## Provider tests

The provider tests (59) pass: client metrics and stream accounting, the correctness gate, request ordering and cancellation, `describe` and `validate` output, and the trace hook.

## Two-host smoke (development tree)

With the 0.2.0 wheels, vLLM 0.31.0 and the pinned vllm-metal fork on both hosts, Qwen3-0.6B (bf16) with `PP=2`, `TP=1`, CUDA first, ran through the provider on the Thunderbolt 4 link: the correctness gate passed with clean link health, cleanup was confirmed, and TPOT was 20.73 ms against the 21.19 ms reference. A single-node run on Linux gave 8.09 ms. The Metal-first orientation was **not** repeated in this smoke.
