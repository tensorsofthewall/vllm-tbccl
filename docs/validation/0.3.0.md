# vllm-tbccl 0.3.0 validation (release candidate draft)

```{warning}
**This is not a certification.** vllm-tbccl 0.3.0 is a minor release of 0.2.1 whose wheels bundle TBCCL 0.7.0 (C ABI 1, wire protocol 4). No adapter source changed since 0.2.1; this page records the validation of the development tree that release candidate 0.3.0rc1 is prepared from. The candidate has not been published yet, so the release-artifact checks below are listed as not done.
```

## What changed

The adapter source is unchanged since 0.2.1. The differences are the TBCCL that the wheels bundle (0.7.0rc1 instead of 0.6.1) and the documentation of the runner requirement.

## Tests on a build against the TBCCL 0.7.0 development tree

| Check | Result |
|---|---|
| Linux adapter test suite (CPython 3.12, vLLM 0.31.0) | 254 passed |
| macOS adapter test suite (CPU environment) | 250 passed |
| Pipeline-boundary benchmark through the real `GroupCoordinator` (`pg_pingpong.py`), 1 to 512 tokens, both orientations | payload verified; round trip about 0.8 ms at 1 token and about 7 ms at 512 tokens |
| Single host, two CUDA ranks, 8 prompts | 8 of 8 token-identical to the single-rank reference |
| Cross-host, Linux CUDA and macOS CPU, 8 prompts, both orientations | 7 of 8 identical in each orientation; the one difference is a near-tie in the next-token probabilities |

## Not yet done for this release

- The CUDA and Metal pairing with the pinned vllm-metal fork has not been run with the 0.7.0 development tree; its validation rests on the earlier 0.2.x qualification until it is run on the published candidate.
- The CI-built wheels of 0.3.0rc1, their checksums, SBOMs and attestations, and a clean-install test of the published wheels on both hosts.
- The current-release entry in the ecosystem manifest, which is changed only after the GitHub release exists.
